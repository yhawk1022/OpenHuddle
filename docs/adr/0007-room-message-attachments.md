# ADR-0007 房间消息附件

- **状态**：已采纳
- **日期**：2026-11-23
- **关联模块**：[消息接口和数据模型](../ARCHITECTURE.md#5-核心数据模型与接口契约草案)

## 1. 背景

群聊和私聊需要支持发图、上传音频与浏览器录音。附件须继承房间成员权限、消息幂等键和撤回语义，并兼容单机 PGlite 与 PostgreSQL 部署。

## 2. 备选方案

1. 将 Base64 存入消息载荷。实现简单，但会放大消息列表传输，并使增量读取承担二进制读取成本。
2. 单独上传至对象存储。可支持更大文件，但需要额外基础设施，以及处理上传成功、消息失败时的孤立对象。
3. 复用消息发送接口，在同一事务中将二进制写入独立数据表。保留单机部署方式，消息列表仅需读取附件元数据。

## 3. 决策

- 采用方案 3。每条消息可选一个附件，最多 8 MiB。图片允许 JPEG、PNG、GIF 和 WebP。音频允许 WebM、Ogg、MP4、MP3 和 WAV。其他文件以 `application/octet-stream` 上传，附带经校验的文件名，并以下载方式返回原始字节。
- 发送接口接收标准 Base64 字符串，先限制请求大小，再校验解码后大小与媒体格式。附件消息可省略正文内容，保留原有消息类型和治理规则。
- 附件二进制与消息在同一事务写入。正文和附件元数据按 `seq` 增量同步。二进制按需读取，仅当前房间成员有权限。撤回时删除二进制，删除房间时级联清理。

## 4. 影响

- 反向代理转发发送请求时需留出 Base64 编码和 JSON 开销。建议允许至少 12 MiB 请求体。数据库备份包含附件二进制，容量需按实际附件用量规划。
- Agent 可经鉴权的 REST 接口收发附件，并由接入方决定如何将媒体提供给模型。公开分享页的访问范围限于消息的文本内容。
- 网页选图与 Codex 生成图片在发送前处理超过 8 MiB 的文件。网页使用画布重新编码，必要时等比例缩小，动图超限时发送静态画面。Codex 等比例缩小并重新编码 PNG。两端最多读取 64 MiB 原图，Codex 对需要压缩的 PNG 仅解码非交错且最多 1600 万像素的文件。发送方只上传压缩后的字节，服务器沿用 8 MiB 上限。
- 网页聊天栏接受浏览器剪贴板提供的图片与文件。粘贴后可预览图片或查看文件名，文字仍走原生粘贴。文件沿用房间鉴权、撤回和 8 MiB 上限。

## 5. Codex 自动图片回复

Codex 本地监听器根据触发消息的服务端身份印章和发图请求启用图片输出。每次推理尝试使用独立的临时工作目录。图片回合启用 Codex 的 `workspace-write` 沙箱，只为该目录开放写入，关闭沙箱网络与提权审批。

Codex 在目录根生成 `reply.png`，最终回复可作为图片说明。监听器在推理成功后读取指定名称的普通 PNG 文件，校验大小和文件头，拒绝符号链接和硬链接。监听器负责凭原 Agent 身份发送带引用序号的消息，之后清理临时目录。发送冲突沿用原幂等键和附件。无有效图片或触发超时降级时返回文本反馈。

这套路径复用 Web 已有的附件展示和服务器存储。PNG 编解码随单文件 CLI 一起分发。生成图片依赖本机 Codex 回合可用的绘制能力。既有监听器在更新 CLI 后需要重新启动才能使用新路径。
